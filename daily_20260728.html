Agentic CPU-GPU Scheduling for Heterogeneous AI Workloads

AI 助手现在会自己调用一堆小工具, 这些工具有的吃 GPU 有的其实 CPU 就够了. Brown 团队发现 19 个常用 AI 工具里只有 11 个真的需要 GPU, 4 个是「看起来该用 GPU 其实 CPU 更快」(因为数据搬运太慢), 还有 3 个根本无所谓. 他们给 AI 助手配了一个「调度小秘书」— 工具要跑之前, 先看显存够不够, 显存紧就让它去 CPU 排队. 实测比「无脑全 GPU」省了 30% 显存, 还能让长任务不卡短任务.

📖 专业版问题讲解 (展开)
Lu 与 Reda (Brown University) 针对当前 Agentic AI 系统在共享 GPU 与 CPU 基础设施上「一刀切 GPU 优先调度」的次优问题, 给出四项贡献: 一是对 19 个 AI 工具做 GPU 与 CPU 倾向实证分析, 发现只有 11 个工具真正偏好 GPU, 4 个其实更适合 CPU (PCIe 数据搬运反而是瓶颈), 3 个完全无所谓, 1 个明确 CPU 优先; 二是把设备调度形式化为三选项空间 — 立即 GPU、排队 GPU、CPU 卸载, 受显存预算约束; 三是设计 LLM 代理 + 算法运行时监控器的协同调度器, 监控器通过 running averages、对称 reprobing、swap reprobing、exploration hints 扩展 LLM 视野, 但不直接做决策, 避免 LLM 频繁决策的延迟成本; 四是揭示 GPU 利用率争用与 VRAM 容量争用是导致端到端延迟偏离静态画像的两个主要运行时因子. 实验在 agentic 工作负载上端到端延迟降低 30% 以上, VRAM 占用降低 30%.
⚙️ 方法：方法上基于 19 个真实 AI 工具的 GPU 与 CPU 倾向画像, 配合三选项设备调度 (立即 GPU、排队 GPU、CPU 卸载), 再加上 LLM 代理与算法运行时监控器的解耦协同设计. 监控器通过 running averages、对称 reprobing、swap reprobing、exploration hints 四个机制扩展代理视野, 但不直接做决策; 关键创新是把调度决策权交给 LLM, 把运行时观测交给轻量算法, 避免 LLM 频繁决策带来的延迟成本.
⚖️ 取舍：优势是第一次把「工具、设备、显存」三层调度显式拆开, 解决了 agentic 系统的 GPU 误分配问题. 局限是工具画像需要事先 profile, 19 个工具可推广, 但新工具接入需要重新画像, 缺少在线自适应画像能力; LLM 代理与监控器的协同延迟是新的潜在瓶颈.
📊 效果：在 agentic AI 工作负载上, 端到端延迟相对「全 GPU 优先」基线降低 30% 以上, VRAM 占用降低 30%. 研究同时揭示 GPU 利用率争用与 VRAM 容量争用是导致端到端延迟偏离静态画像的主要运行时因子, 这正是之前调度器的盲区.
🏢 团队：Tianxi Lu, Sherief Reda → Brown University, USA

Unified Static-Dynamic Pruning for Efficient LLM Inference

大模型推理时, 每次生成一个词都要把所有参数都过一遍, 太慢. 一种思路是「剪枝」— 把不重要的参数剪掉, 但只剪一次 (静态) 遇到新输入就傻了, 每次输入都重新剪 (动态) 又太花时间. 韩国首尔大学团队搞了个「动静结合」的方案: 静态部分先做基础剪枝, 动态部分只对剪过的参数按输入动态调整. 实测 GPU 推理快了 1.5-2.3 倍, 而且对模型准确率几乎没影响.

📖 专业版问题讲解 (展开)
Kim, Lee 与 Do (Seoul National University) 针对 LLM 自回归解码中低计算强度与带宽受限的推理瓶颈, 提出 SPDP 统一稀疏推理框架, 整合两件事: 一是非结构化静态剪枝提供基础稀疏度, 二是输入自适应动态剪枝应对输入差异. 关键技术贡献有三项: 其一是 Tiled-Column-wise Bitmap Compressed (简称 Tiled-CBC) 格式, 兼顾压缩率与 GPU 访问模式; 其二是 CUDA-core spMspV 内核实现 Hybrid Activation-aware Dynamic Shared-Memory Bitmap Decoding (简称 HAD-SMBD), 在共享内存层做细粒度运行时解码; 其三是静态与动态协同的稀疏度调度策略. 在多个 LLM 推理 benchmark 上端到端加速 1.5 到 2.3 倍, 困惑度退化小于 1%.
⚙️ 方法：方法上采用三层协同的稀疏解码方案: 第一层是 Tiled-CBC 格式 (一种按列分块的位图压缩格式), 用来编码静态剪枝后的冗余权重; 第二层是 HAD-SMBD (一种在共享内存里做激活感知的位图动态解码机制), 在共享内存层按输入动态选择细粒度稀疏; 第三层是 spMspV 内核 (稀疏矩阵乘以稀疏矩阵再乘向量), 用来避免稠密矩阵乘法的冗余计算.
⚖️ 取舍：优势是第一次把静态与动态剪枝统一到一个格式加一个 kernel, 简化了推理引擎的设计空间. 局限是 Tiled-CBC 格式对稀疏模式敏感, 非均匀稀疏场景下压缩率退化; 动态剪枝需要 GPU shared memory 达到一定阈值, 消费级 GPU 适用性受限.
📊 效果：在 LLaMA 类大模型推理上, 端到端加速 1.5 到 2.3 倍, 困惑度退化小于 1%. 此外, Tiled-CBC 格式相对传统 CSR 与 CSC 两种压缩方式, 压缩率提升 30% 以上, 解码吞吐提升 2 倍以上.
🏢 团队：Jinhyeok Kim, Yejoon Lee, Jaeyoung Do → Seoul National University, South Korea

PRISM: Evaluating POSIX Storage Systems for AI Research Workflows

AI 研究员每天读写几千个数据文件, 跑实验前要打开老数据, 跑完要存 checkpoint, 写代码时还要不停 git pull. Meta FAIR 团队发现, 现有存储系统测试都只看「峰值带宽」, 根本没考虑研究员工作的真实节奏: 一会儿疯狂读, 一会儿写一点点, 一会儿又在编辑器里翻代码. 他们做了个叫 PRISM 的测试套件, 按真实 AI 研究的节奏 (数据导入 + checkpoint 读写 + 开发者工作流) 模拟, 发现 Lustre / WekaFS / GPFS 实际表现跟厂商标称值差 5 到 10 倍.

📖 专业版问题讲解 (展开)
Kumar 等 6 人 (FAIR at Meta) 针对 AI 研究工作流 (与传统 HPC 不同) 高度依赖 POSIX 兼容文件系统 + 短爆发异构 IO 的特性, 提出 PRISM 评估框架, 贡献四点: 其一是复现三类真实 AI 研究工作负载 — 数据导入、checkpoint I/O、开发者工作流 (编辑器、git、日志); 其二是揭示传统存储 benchmark 只测峰值吞吐, 严重低估 POSIX 兼容接口下的真实性能; 其三是在 Lustre、WekaFS、GPFS、本地 NVMe 上对比, 显示真实工作负载下, POSIX 性能与厂商标称峰值差距 5 到 10 倍; 其四是提出「POSIX 友好性 + 短爆发异构 IO 适配度」作为新的存储选型指标. Meta 内部已用 PRISM 选型 GPU 集群存储后端.
⚙️ 方法：方法上由三部分组成: 数据导入工作负载 (大规模读 + 小文件写) + checkpoint I/O (大块顺序写 + 突发读) + 开发者工作流 (小文件随机读 + git 与编辑器访问模式). 在 Lustre、WekaFS、GPFS、本地 NVMe 四种存储后端上做对比, 评估指标包括 POSIX 操作延迟分布 + 端到端研究周期时间.
⚖️ 取舍：优势是第一次把 AI 研究员真实工作节奏 (编辑器、git、checkpoint、数据导入) 纳入存储 benchmark, 改变了 GPU 集群存储选型方法论. 局限是评估只在 Meta 内部 GPU 集群环境验证, 其他公司 (Google、Microsoft) 工作流差异可能影响结果外推; WekaFS 等新存储的优化路径可能因 PRISM 评测压力而加速.
📊 效果：在 PRISM 真实工作负载下, Lustre、WekaFS、GPFS 的端到端性能与厂商标称峰值吞吐差距 5 到 10 倍; 短爆发异构 IO 场景下, 传统存储的 POSIX 性能与本地 NVMe 的差距比预期小得多, 提示选型应优先 POSIX 兼容性而非峰值带宽.
🏢 团队：Adithya Kumar, Aditya Basu, Jacob Kahn, Parth Malani, Leo Huang, Kalyan Saladi → FAIR at Meta, USA

Decoupled Attention Fusion: Accelerating RAG with Efficient KV Cache Reuse

RAG (检索增强生成) 让大模型回答前先查一堆文档, 问题是每查一次都要重新算一遍注意力, 等半天. 蚂蚁集团 + 东南大学团队搞了个叫 DAF 的方法, 把注意力拆成「重要 token 看自己」+「问题看文档」+「结果拼起来」三段, 重要 token 的注意力预先算好缓存, 后续 query 直接复用. 实测长文档 RAG 场景下, 首次出字 (TTFT) 延迟降低 60% 以上, 准确率比之前的 CacheBlend 还高.

📖 专业版问题讲解 (展开)
Wu 与 Liu 等 (Ant Group + Southeast University) 针对长上下文 RAG 场景下 KV cache 复用面临的「分布不匹配」难题 — 离线缓存的跨文档注意力模式无法支持跨文档推理, 同时 CacheBlend 等方案在长上下文下准确率严重退化 — 提出 Decoupled Attention Fusion (简称 DAF) 框架, 把注意力过程解耦为三个集成阶段: 第一阶段用 important-token self-attention 恢复缺失的跨文档注意力; 第二阶段用 question-document self-attention 做标准推理; 第三阶段用 state fusion 拼接两段结果. 在长文档 RAG benchmark 上, TTFT 降低 60% 以上, 准确率高于 CacheBlend. 已集成进蚂蚁 RAG 推理引擎.
⚙️ 方法：方法采用三阶段解耦注意力 (Decoupled Attention Fusion, 简称 DAF): 第一阶段是 important-token self-attention, 用预先选好的重要 token 做跨文档注意力, 恢复离线缓存里缺失的跨文档关联; 第二阶段是 question-document self-attention, 用问题与文档做标准的多头注意力; 第三阶段是 state fusion, 把前两段的状态拼接起来作为最终输出. 关键创新在于 KV cache 复用时不再丢失跨文档注意力, 通过 important-token 选择性重算 + 状态融合两步弥补分布差异.
⚖️ 取舍：优势是解决了 KV cache 复用的「分布不匹配」难题, 兼顾延迟与准确率, 对 RAG 服务化意义重大. 局限是 important-token 选择需要预训练分类器, 跨域迁移性需要验证; 状态融合增加少量计算, 在超短上下文场景下收益不明显.
📊 效果：在长文档 RAG 基准测试上, 首次出字时间 (TTFT) 相对 CacheBlend 方案降低 60% 以上, 准确率高于 CacheBlend. 在蚂蚁内部 RAG 服务落地后, 长文档响应延迟从秒级降到亚秒级.

NUMA balancing hampering performance of spiking network simulations

神经形态芯片 (模拟人脑神经元放电的芯片) 仿真时, 数据在不同 CPU 核之间搬运很慢. Jülich 超算中心 + 亚琛工大 + 挪威生命科学大学联合发现, 即使是 HPC 集群, NUMA (非统一内存访问) 平衡没做好, 脉冲神经网络仿真性能能掉 30% 到 50%. 他们给 NEST 仿真器加了自动 NUMA 感知调度, 在 Jülich 的超算上实测, 大规模 spiking 网络仿真时间从 6 小时降到 3.5 小时.

⚙️ 方法：方法上系统性剖析 NEST 仿真器在 HPC 集群的 NUMA 行为, 配合 MPI-NUMA 亲和性优化, 再加上内存带宽争用分析, 最后集成自动 NUMA-aware 调度. 关键创新是把脉冲神经网络的 spike 传播图映射到 NUMA 拓扑, 减少跨节点内存访问.
